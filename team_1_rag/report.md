# Отчёт по личной задаче
## Vectorization and database preparation
### Векторизация и подготовка базы

## 1. Объём выполненной работы

Личная задача включает:

- Этап 3, задача 1 — подключение одной изученной embedding-модели.
- Этап 3, задача 2 — создание настоящих embeddings и сохранение связи между вектором и исходным текстовым чанком.
- Этап 4, задача 2 — подготовка вектора вопроса той же моделью.
- Дополнительная задача — объединение подготовки текста, векторизации и сохранения индекса в отдельный запуск.

## 2. Используемые файлы

- `source/source.txt` — исходный текст учебного центра.
- `preparation/chunking.py` — загрузка, очистка и разделение текста на чанки.
- `rag/embeddings.py` — загрузка модели, создание embeddings и запуск подготовки индекса.
- `rag/vector_store.py` — сохранение и повторная загрузка текстов и векторов.
- `rag/query_embedding.py` — отдельная подготовка вектора вопроса.
- `index/embeddings.npy` — сохранённая матрица векторов.
- `index/chunks.txt` — соответствующие текстовые чанки.

## 3. Этап 3. Подключение модели и создание embeddings

### 3.1. Используемая модель

Выбрана многоязычная модель:

`paraphrase-multilingual-MiniLM-L12-v2`

Модель загружается функцией `load_model()` из файла `rag/embeddings.py`.

В пределах одного запуска подготовки индекса создаётся один объект модели. Этот объект используется для векторизации всех текстовых чанков.

### 3.2. Создание векторов

Для преобразования текста используется функция:

`create_embeddings(chunks, model)`

Внутри применяется:

`model.encode(chunks, convert_to_numpy=True)`

Таким способом создаются настоящие числовые embeddings, а не учебные или вручную заданные векторы.

### 3.3. Результат векторизации

- Количество текстовых чанков: 24.
- Количество векторов: 24.
- Форма матрицы embeddings: `(24, 384)`.
- Размерность одного вектора: 384.
- Тип данных: `float32`.

Каждому текстовому чанку соответствует вектор с той же позицией в матрице embeddings.

### 3.4. Проверка соответствия текста и векторов

Проверено количество текстовых записей и векторов.

Дополнительно embeddings были повторно рассчитаны для сохранённых текстовых чанков с использованием той же модели и сравнены с сохранённой матрицей.

Результат:
- Размеры совпадают: `True`.
- Максимальное отличие: `0.0`.
- Векторы совпадают: `True`.

Это подтверждает сохранение соответствия между текстом и его вектором.

## 4. Сохранение и повторная загрузка индекса

Для сохранения и загрузки используется файл `rag/vector_store.py`.

Функция `save_index()` сохраняет:
- числовые векторы в `index/embeddings.npy`;
- текстовые чанки в `index/chunks.txt`.

Функция `load_index()` восстанавливает тексты и матрицу векторов.

Соответствие сохраняется благодаря одинаковому порядку записей в обоих файлах.

Проверено:
- индекс успешно записывается на диск;
- индекс успешно загружается после запуска;
- количество текстов совпадает с количеством векторов;
- повторная подготовка заменяет существующие файлы, а не добавляет новые записи в конец.

## 5. Этап 4. Подготовка вектора вопроса

Для выполнения этой задачи создан отдельный файл:

`rag/query_embedding.py`

В нём используется та же модель и общая функция `create_embeddings()` из `rag/embeddings.py`.

Функция:

`create_query_embedding(query, model)`

преобразует вопрос пользователя в числовой вектор.

Векторизация вопроса выполняется отдельно от подготовки всей базы. Сохранённый индекс загружается с диска, embeddings исходных чанков повторно не рассчитываются.

### Результат проверки

Тестовый вопрос:

«Сколько стоит обучение Python?»

Полученные результаты:
- Форма вектора вопроса: `(1, 384)`.
- Количество текстовых чанков в индексе: 24.
- Размерность векторов индекса: 384.
- Совпадение размерностей: `True`.

## 6. Дополнительная задача. Отдельный запуск подготовки индекса

В файле `rag/embeddings.py` объединены следующие действия:

1. Загрузка исходного текста.
2. Очистка текста.
3. Разделение текста на чанки.
4. Загрузка embedding-модели.
5. Создание векторов.
6. Сохранение индекса.
7. Повторная загрузка и проверка сохранённых данных.

Подготовка индекса запускается отдельной командой:

`python .\team_1_rag\rag\embeddings.py`

Обработка вопроса проверяется отдельно:

`python .\team_1_rag\rag\query_embedding.py`

## 8. Примечание о формате хранения

В текущей реализации используются два файла:

- `index/embeddings.npy` — числовая матрица embeddings.
- `index/chunks.txt` — текстовые чанки.

Такой способ хранения обеспечивает соответствие текста и вектора по одинаковому порядку записей.

В общем задании отдельно указано требование использовать текстовый формат `database/database.txt` (этап 3, задача 3).

Переход на этот формат не входит в выделенный личный объём данной работы. Поэтому он не отмечается как выполненный. Его необходимо отдельно согласовать и учесть при подготовке общей сдаваемой версии проекта.
